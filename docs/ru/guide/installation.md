# Установка, обновление и восстановление

[Документация на русском](../README.md) · [Подробное руководство на английском](../../guide/installation.md)

Установка APK добавляет Manager, но сама по себе не даёт root. На устройство также нужно записать исправленный загрузочный образ с подходящим LKM.

## Требования

- ARM64, Android 12 / API 31 или новее и Linux 6.1 или новее.
- Готовые LKM: `android14-6.1`, `android15-6.6`, `android16-6.12`, `android17-6.18`. Не выбирайте KMI только по версии Android.
- Рабочий способ записи и восстановления загрузочных разделов, обычно с разблокированным bootloader.
- Оригинальные образы установленной прошивки и точное знание раздела и A/B-слота.

Эти команды только читают информацию:

```sh
adb shell uname -r
adb shell getprop ro.product.cpu.abi
adb shell getprop ro.build.version.sdk
adb shell getprop ro.boot.slot_suffix
```

Перечень KMI — матрица сборки, а не подтверждение совместимости каждого устройства.

## Стандартная установка LKM

1. Скачайте Manager из [опубликованных релизов](https://github.com/wuluoy-creator/ZySU/releases). В Actions используйте итоговый артефакт `Manager-arm64-v8a`.
2. Откройте установку из области состояния на главном экране. Выберите оригинальный `boot.img` или `init_boot.img` в зависимости от расположения ramdisk на устройстве.
3. Используйте встроенный LKM или собственный `.ko`, соответствующий целевому ядру. Если Manager не определяет KMI, потребуется ручной выбор. В `init_boot` нет ядра, поэтому этот образ может не содержать нужной информации.
4. При необходимости задайте SuperKey и выполните исправление. При выборе локального файла результат сохраняется в `Download`; автоматической записи в раздел не происходит.
5. Проверьте журнал, запишите результат в соответствующий раздел и слот подходящим для устройства способом, затем перезагрузитесь.

Стандартный `boot-patch` помещает ksuinit и LKM в ramdisk и загружает модуль на раннем этапе запуска. Также доступно извлечение загрузочных образов из архива прошивки по HTTPS. Ориентируйтесь на форматы и разделы, фактически обнаруженные интерфейсом.

При наличии root доступна прямая установка. На A/B-устройствах также предлагается установка в неактивный слот. Для неё необходимо проверить образ и KMI целевого слота, записанного обновлением OTA. Прямая установка изменяет разделы.

## Прямая инъекция LKM в ядро boot

Для локального файла и прямой установки можно выбрать `boot-patch-v2`. Метод работает с содержащим ядро `boot.img` / разделом `boot`, а не с `init_boot` или `vendor_boot`.

При выборе встроенного LKM KMI определяется из целевого ядра; обычный диалог выбора KMI не используется. Формат, символы и ABI проверяются, поэтому не каждый boot-образ пригоден. Это не поддержка `CONFIG_KSU=y`. При переключении методов также возможна очистка старого ramdisk-патча в том же слоте; сохраняйте соответствующие оригиналы и журналы.

В CLI параметр `boot-patch --out` означает каталог, а `boot-patch-v2 --output` — файл. Подробности — в [справочнике CLI](../../ksud-cli.md).

## Аутентификация и первый запуск

Без SuperKey Manager распознаётся согласно конфигурации подписи. Для APK с собственной подписью нужна соответствующая конфигурация доверия в LKM; см. [интеграцию](how-to-integrate.md).

Если SuperKey настроен, используйте ключ, заданный при исправлении образа. Обход подписи означает аутентификацию Manager только по SuperKey, а не отключение проверки подписи модулей Linux. «Разрешить shell» позволяет Android shell UID запрашивать root; включение adbd — отдельная настройка.

После перезагрузки проверьте распознавание ядра, аутентификацию, совместимость UAPI и версию ksud. При необходимости синхронизируйте встроенную программу через карточку ksud. SUMHP уже встроен: `auto` выбирает подходящий OverlayFS, затем Magic Mount; SUMH выбирается явно. Изменения OverlayFS / Magic Mount обычно требуют перезагрузки.

## Обновление и восстановление

Manager проверяет официальные релизы; канала CI-обновлений нет. APK, ksud и модуль ядра — отдельные компоненты. После обновления APK при необходимости синхронизируйте ksud, заново исправьте загрузочный образ и перезагрузитесь. После OTA повторно проверьте целевой KMI.

Исходный код и будущие релизы объединены в публичном репозитории `wuluoy-creator/ZySU`. Если установленный APK ещё проверяет `ZySU-Releases`, один раз вручную установите APK с новым адресом обновлений из [ZySU Releases](https://github.com/wuluoy-creator/ZySU/releases). Для обновления поверх установленной версии нужны та же подпись и больший код версии. Копирование старого APK в новый репозиторий не меняет встроенный адрес. Старый репозиторий сохраняется для истории и информации о переходе.

Восстановление образа и полное удаление — разные операции. Восстановление использует подходящие резервные копии или удаление соответствующего патча. Полное удаление стирает userspace и модули, пытается восстановить загрузочный образ, удаляет Manager и через примерно пять секунд запрашивает перезагрузку. Текущая реализация продолжает удаление и перезагрузку даже при ошибке восстановления, поэтому заранее подготовьте оригинальные образы и внешний способ восстановления. Удаление APK не восстанавливает загрузочные разделы.

Если устройство не загружается, восстановите оригинальные образы прошивки в реально изменённые разделы и слот. При сбоях модулей может помочь безопасный режим: ранний hook ввода отмечает его после как минимум трёх нажатий уменьшения громкости, после чего userspace отключает модули. Распознавание зависит от момента загрузки и не заменяет способ восстановления образов.

В отчёте укажите устройство, прошивку, KMI, версии компонентов, метод исправления, слот и журналы. Команда `ksud install` устанавливает только userspace и не заменяет установку загрузочного образа.
