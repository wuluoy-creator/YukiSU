# Kasumi 优化与回归验证

这次改动保持协议版本 17、ioctl 编号、UAPI 结构和挂载后端选择顺序。优化集中在资源生命周期、失败处理和重复工作；没有增加新的隐藏策略。

## 修改范围

| 范围 | 改动及作用 |
| --- | --- |
| 规则回收 | RCU 回调只移交资源，由工作队列释放可能休眠的 path/dentry 引用；清空和退出等待回收完成。 |
| 目录遍历 | 在 RCU 内持有合并目标 dentry 引用，遍历结束后释放；路径缓冲区归每次遍历所有；通过内部目录回调识别递归，避免睡眠和 CPU 迁移破坏共享状态。 |
| 属性修改 | setattr 使用源挂载的写保护和 idmap，保留已有 ATTR_FILE 转发及旧内核接口分支。 |
| 查询和内存 | 精确虚拟子节点查询使用已有哈希桶；常见 xattr 列表使用 256 字节缓冲区，遇到 ERANGE 才分配完整缓冲区；移除失效的每 CPU 内存分配。 |
| 用户空间 | 按内核返回长度读取规则和 hooks；能力查询失败明确返回错误；拒绝无法完整表示的 maps 路径；隐藏规则恢复失败保留重试状态。 |
| 持久化 | 区分不存在的规则文件与读取/解析失败；损坏配置不能再被解释为用户主动清空规则。 |
| 管理器 | 多步骤读取与本管理器的写操作互斥；规则页只查询规则相关数据；模块规则比较使用集合；内核日志只保留最近 1000 条匹配行；JNI 报告规则/hooks 查询错误。 |

规则刷新从一次内核快照加五次守护进程请求，缩减为一次内核快照加一次守护进程请求。这是调用次数变化，不是实测延迟结论。精确查询的哈希优化保留了原有前缀查找分支。

## 主机回归测试

在仓库根目录的 Linux 环境执行：

```sh
python3 scripts/ci/test_kasumi_core.py --cc clang
python3 scripts/ci/test_kasumi_vfs_helpers.py --cc clang
python3 userspace/ksud/tests/run_kasumi_host_tests.py --cxx g++
```

内核测试提取生产函数体，模拟 VFS、RCU 和工作队列，检查引用持有、释放顺序、源挂载写保护、idmap、嵌套目录遍历，以及 xattr 的边界和错误分支。用户空间测试使用模拟 ioctl 和存储，覆盖响应长度、能力错误、路径边界、规则恢复及持久化失败。

Windows 上，两个内核测试可以使用 `--cc` 指向 Android NDK 的 `clang.exe`；它们调用同目录的 `ld.lld.exe` 生成本机测试程序。用户空间测试可使用 `--zig` 指向 Zig 可执行文件。Windows 的 ioctl 类型头仅供模拟传输使用，不能用于验证 Android ABI。

自动化入口是 `.github/workflows/kasumi-tests.yml`。这些测试覆盖具体修改逻辑，不能替代完整内核构建或真实并发压力测试。

管理器验证命令，在 `manager` 目录执行：

```sh
./gradlew :app:compileDebugKotlin :app:testDebugUnitTest :app:externalNativeBuildDebug
```

## 发布前的内核与设备验证

使用现有 `build-lkm.yml` / `ddk-lkm.yml` 构建支持的四个 KMI：android14-6.1、android15-6.6、android16-6.12、android17-6.18。设备验证应至少覆盖以下场景：

1. 分别使用 Kasumi、OverlayFS 和 Magic 后端启动含模块的系统，检查模块优先级、链接、读写、属性和目录内容。
2. 在目录持续遍历时添加、删除和清空规则，检查目录结果及内核日志，确认没有释放后使用、原子上下文睡眠或引用泄漏。
3. 对源挂载执行只读/可写切换，并验证 chmod、chown、truncate、已有文件句柄和挂载 idmap 的行为。
4. 检查普通与大型 xattr 列表，包括 size-only 查询、短缓冲区、OverlayFS 属性过滤和原生错误返回。
5. 在测试设备中验证隐藏规则文件缺失、损坏、不可读、恢复正常，以及控制请求短暂失败后的重试；读取失败期间不得清除或覆盖原有规则。
6. 在管理器同时刷新状态和保存配置，确认操作结果、日志、规则状态以及配置应用失败提示正确。

设备结果应记录 KMI、文件系统、启用的功能及内核日志。本次主机测试没有证明所有设备上均无回归。
