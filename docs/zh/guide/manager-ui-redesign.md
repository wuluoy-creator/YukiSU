# 管理器 UI 与页面结构改造

> 状态：2026-10-02 在独立“挂载与隔离”页面基础上，将挂载视图整理、自定义 su 路径迁入“隔离设置”。原内核页面保留其他内核功能、Magisk 兼容及高级安全。本轮通过构建、51 项单元测试与 Lint，未进行真机验收。

## 技术栈与改造边界

管理器继续使用项目现有的 Kotlin、Jetpack Compose、Material 3 与 Compose Destinations。列表、设置、弹窗、导航和反馈均为 Android 原生实现，未为参考图引入 Web、React Native 或新的 UI 框架。

改造集中在视觉、信息层级、页面组织和界面生命周期。Root 授权、SuperKey 认证、应用配置、模板、模块安装、内核功能读写、配置格式、维护操作、日志采集和仓库行为继续使用原有实现。原来的运行条件、内核能力判断、保存结果检查、失败回读与回滚保留。新工作区只重新组织已有入口，不增加 Root 能力。

参考图用于建立统一的工具应用语言：GitHub 的列表对齐和清晰分组，LocationSpoofer 的中性背景和明确主操作，聊天页的干净空状态，以及内容页中文字和辅助信息的层级。没有照搬参考应用的页面结构，也没有引入瀑布流。

## 页面结构

底部导航统一为 **首页、授权、模块、设置**。首页和设置可在未取得有效管理器权限时进入；授权与模块继续受原有 Root 条件控制。保留分类的工作区使用铺满宽度、等比例分配空间的原生标签；长文字允许换行，切换时立即更新内容并清除输入焦点。首页、授权列表、模块和模块仓库没有分类标签。

```text
首页
├─ 顶部左侧：安装 / 运行状态、认证与版本信息
├─ 顶部右上：ksud 守护进程 → 版本与同步弹窗
├─ 顶部右下：Kasumi 内核 → 运行信息弹窗
├─ 连续内容：更新、内核版本、设备信息
├─ 安装 / 更新：沿用原安装流程
├─ 注入状态摘要 → YukiZygisk 独立页
└─ 工具栏 → 诊断与日志、重启菜单

授权
├─ 直接显示应用：搜索、排序、授权列表 → 应用配置
├─ 右上角策略图标 → 配置模板、SuperKey、默认卸载模块策略
└─ 右上角记录图标 → Root 请求与命令记录

模块
├─ 直接显示现有模块管理、更新、配置、WebUI 与快捷方式
├─ 工具栏 → 模块仓库 → 仓库源
└─ 工具栏 → YukiZygisk 独立页
   ├─ 顶部：YukiZygisk 启用开关
   └─ 启用后连续显示：Zygote、模块、原生注入、功能配置与日志设置

设置
├─ 外观：语言、主题、配色、背景、显示大小、返回手势
├─ 内容与显示：首页简洁模式、模块信息、内容显隐
├─ 应用与更新：更新偏好、守护进程更新、WebUI 引擎
├─ 挂载与隔离
│  ├─ 挂载：Kasumi 挂载配置
│  ├─ 隔离设置：挂载视图整理、自定义 su 路径、卸载路径与 Kasumi 隔离配置
│  └─ 生效规则：查看、刷新、清除规则
├─ 内核与隔离
│  ├─ 内核功能：其他内核功能开关与 Magisk 兼容
│  └─ 高级安全：SELinux
├─ YukiZygisk → 独立单页，关闭时仍可进入并启用
├─ 诊断与日志
│  ├─ 选项与导出：诊断报告、授权记录入口、Kasumi 调试
│  ├─ 运行日志：Kasumi 日志与内核日志
│  └─ WebUI 调试：仅调试构建显示
└─ 维护与关于：还原、卸载、应用信息
```

首页顶部与设备信息使用同一个滚动区域。ksud 和 Kasumi 摘要保留固定位置；Kasumi 只在管理器和内核有效时调用原状态读取接口，无权限时显示未知状态，刷新不可用。没有权限时仍保留安装、认证和状态说明。内核配置页继续使用 `KsuIsValid`。

## 主要使用流程

### 查看状态与处理更新

打开首页先看到左侧安装 / 运行状态，以及右侧上下排列的 ksud 守护进程和 Kasumi 内核。安装、升级、SuperKey 认证和重启仍通过原有处理器执行。点击 ksud 卡片打开版本与同步弹窗；点击 Kasumi 卡片打开同款原生信息弹窗，查看视图状态、挂载路径、活跃挂载、Hooks 与挂载统计。Kasumi 不再显示模块数、存储占用或页面内展开列表。查看注入运行情况仍从 YukiZygisk 摘要进入独立页。

### 管理应用授权

进入“授权”即可搜索或排序应用，点击应用进入原有配置页面。应用名称优先，包名、版本与状态作为辅助信息；较长文字和操作区域按可用宽度布局。

通用授权策略从右上角调节图标进入“策略与模板”，包括原有配置模板、SuperKey 和默认卸载模块策略。单个应用的授权与配置仍在应用详情中进行。右上角时钟图标进入“授权记录”，图标可长按查看说明。授权日志已开启时显示原日志查看器；未开启时显示说明和直达“内核功能”分类的入口，不会自动打开日志功能。返回记录页时会重新读取可用状态。

### 管理模块及其运行环境

“模块”入口直接显示模块管理，保留搜索、状态、管理操作与原有业务处理器。模块仓库是独立页面，显示模块目录并提供下载、安装与仓库源管理。

YukiZygisk 通过设置中的独立入口、首页注入状态摘要或模块工具栏打开。页面顶部是从内核功能中迁入的 YukiZygisk 启用开关；关闭时仅显示开关，确认启用后在同一滚动区域显示监控、配置和日志，不设置概览 / 配置 / 诊断分类。设置入口不依赖 YukiZygisk 的启用状态，继续沿用原有管理器有效性检查。Kasumi 挂载设置位于“设置 → 挂载与隔离 → 挂载”；每个模块自身的配置、WebUI 和快捷方式仍位于模块操作区域。

### 调整管理器设置

设置首页按用途分组，YukiZygisk 使用独立入口。外观、内容与显示、应用与更新、维护与关于在同一设置导航中展开，工具栏与系统返回均回到类别索引。每个类别保留可保存的滚动与页面状态；再次进入时读取已有偏好。

外观仍支持既有品牌色、动态配色、浅色 / 深色 / 跟随系统、自定义背景、透明度、背景压暗、语言和 DPI。内容显隐只影响原有信息展示，不改变功能数据。更新开关、CI 更新条件、自动更新 ksud 和 WebUI 引擎偏好保持原逻辑。

### 查看隔离、内核功能与诊断

“挂载与隔离”独立页提供挂载、隔离设置、生效规则三个等宽分类；“内核与隔离”保留内核功能、高级安全两个等宽分类。内核功能仍依据原有支持状态启用或禁用；需要重启、生效失败和回滚的反馈来自原处理逻辑。

诊断从设置进入，首页也提供快捷入口。“选项与导出”保留原诊断报告底部面板：保存使用 Android 系统文档选择器，分享使用系统分享面板。“运行日志”承载 Kasumi / 内核日志。WebUI 调试保留 `BuildConfig.DEBUG` 条件，Eruda 仍依赖已启用调试及对应 WebUI 引擎。

遵循已加载的 `emil-design-eng` 技能，UI 审查使用 Before / After / Why 表格。技能中的实现思路按 Compose 与 Android 原生组件适配，不直接使用 Web CSS 或 JavaScript 示例。

| Before | After | Why |
| --- | --- | --- |
| 多个独立顶层入口，相关设置分散 | 四个底部目的地，按状态、授权、模块与设置组织 | 日常任务入口稳定，减少往返 |
| Kasumi 与 YukiZygisk 的状态、配置、日志混在长页中 | Kasumi 按用途放入首页、挂载与隔离、诊断；YukiZygisk 保持独立页 | 同一目的的内容可以连续处理 |
| 设置逐项堆积，外观与安全设置混排 | 类别索引与聚焦子页 | 更易扫描，降低错误操作机会 |
| 大面积状态色块、独立数字卡与多层容器 | 中性表面、行内状态与单层分组 | 提高信息密度，突出关键操作 |

| 高频导航使用明显位移、弹跳与持续装饰动画 | 即时标签切换、原生点击反馈与克制状态过渡 | 工具操作迅速，减少重复等待 |
| 悬浮菜单逐项弹出且高度固定 | 原生锚定菜单与可测量的文字布局 | 长标签、横屏和大字更稳妥 |
| 内容可能延伸到系统栏或输入法下 | 宿主统一处理安全区、消费 padding 并避让 IME | 避免底部操作与输入被遮挡 |

| 页面切换可能取消已触发的部分界面保存任务 | 对必须完成的持久化使用明确生命周期保护，并向宿主上报忙碌状态 | 保存结果与界面反馈一致 |

浅色模式以白色、浅灰色与深色文字为主；深色模式使用对应中性表面。既有品牌色和动态配色用于选中、主操作与重要状态。圆角、分隔线和阴影遵循共享主题，避免每行独立卡片和重复嵌套。旧外观选择器已移除，保留主题与用户个性化设置。

## 原生适配与状态管理

- 系统栏与键盘：`MainActivity` 统一提供 IME 避让和宽度约束，页面消费宿主 padding；嵌入内容不再创建重复顶栏或重复计算同一安全区。
- 屏幕宽度：主要内容居中限宽；分类标签等宽铺满一行，标签文字、按钮与辅助信息按可用空间换行。横屏和窄屏不依赖固定文本高度。
- 字体与无障碍：保留原生文字缩放、按钮 / 标签 / 开关语义；设置开关整行只暴露一个可切换目标，装饰图标不重复朗读，导航标签持续可见。
- 动效：高频工作区切换即时执行，状态反馈使用现有 Compose / Material 行为并遵循系统动画设置。加载和操作进度继续使用原生进度组件。
- 初始化：`MoreSettingsContent` 在既有配置和 SELinux 状态读取完成后才显示控件。切换类别不会把尚未读取的临时默认值当成用户选择写回。
- 保存：配置仍走原处理器。必须完成的内核功能持久化、运行时后续操作与必要回读不随页面离开直接中断；外观滑块最终保存与已开始的报告文件复制也受到保护。具体工作区忙碌状态由宿主用于限制中途切页。
- 状态恢复：工作区标签和可保存的子页面状态使用 Compose 原生保存机制。后台数据重新进入时仍从原数据源读取；监控只在相应页面活动时执行原有轮询。
