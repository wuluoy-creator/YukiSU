# 管理器 UI 与页面结构改造

> 状态：2026-10-02 本轮页面重组已完成；最终 Debug 构建、51 个单元测试和 Lint 全部通过。尚未进行本轮真机验收。文末列出了验证范围与待验收项目。

## 技术栈与改造边界

管理器继续使用项目现有的 Kotlin、Jetpack Compose、Material 3 与 Compose Destinations。列表、设置、弹窗、导航和反馈均为 Android 原生实现，未为参考图引入 Web、React Native 或新的 UI 框架。

改造集中在视觉、信息层级、页面组织和界面生命周期。Root 授权、SuperKey 认证、应用配置、模板、模块与插件安装、内核功能读写、配置格式、维护操作、日志采集和仓库行为继续使用原有实现。原来的运行条件、内核能力判断、保存结果检查、失败回读与回滚保留。新工作区只重新组织已有入口，不增加 Root 能力。

参考图用于建立统一的工具应用语言：GitHub 的列表对齐和清晰分组，LocationSpoofer 的中性背景和明确主操作，聊天页的干净空状态，以及内容页中文字和辅助信息的层级。没有照搬参考应用的页面结构，也没有引入瀑布流。

## 页面结构

底部导航统一为 **首页、授权、扩展、设置**。首页和设置可在未取得有效管理器权限时进入；授权与扩展继续受原有 Root 条件控制。各工作区内使用原生标签页，切换时立即更新内容并清除输入焦点。

```text
首页
├─ 概览：管理器与内核状态、版本、更新、系统摘要
├─ 系统：Kasumi 状态、挂载与系统信息
├─ 安装 / 更新：沿用原安装流程
├─ 注入状态摘要 → 挂载与注入 / 注入监控
└─ 工具栏 → 诊断与日志、重启菜单

授权
├─ 应用：搜索、排序、授权列表 → 应用配置
├─ 策略与模板：配置模板、SuperKey、默认卸载模块策略
└─ 授权记录：Root 请求与命令记录

扩展
├─ 模块：现有模块管理、更新、配置、WebUI 与快捷方式
├─ 插件：现有插件管理、配置与日志
├─ 工具栏 → 扩展仓库
│  ├─ 模块仓库
│  └─ 插件仓库 → 仓库源
└─ 工具栏 → 挂载与注入
   ├─ 挂载：Kasumi 挂载配置
   ├─ 注入监控：Zygote、模块、原生注入与异常信息
   └─ 注入设置：YukiZygisk 配置

设置
├─ 外观：语言、主题、配色、背景、显示大小、返回手势
├─ 内容与显示：首页简洁模式、模块信息、内容显隐
├─ 应用与更新：更新偏好、守护进程更新、WebUI 引擎
├─ 内核与隔离
│  ├─ 隔离设置：Kasumi 隔离配置、卸载路径入口
│  ├─ 生效规则：查看、刷新、清除规则
│  ├─ 内核功能：现有内核功能开关与 su 路径设置
│  └─ 高级安全：SELinux、动态管理器设置
├─ 诊断与日志
│  ├─ 选项与导出：诊断报告、授权记录入口、Kasumi / 注入调试
│  ├─ 运行日志：Kasumi 日志与内核日志
│  └─ WebUI 调试：仅调试构建显示
└─ 维护与关于：还原、卸载、应用信息
```

“首页 → 系统”仅在核心数据加载完成且管理器和内核有效时显示。没有权限时仍保留概览里的安装、认证和状态说明。内核相关页面内部继续使用 `KsuIsValid`，不会因新导航入口跳过能力检查。

## 主要使用流程

### 查看状态与处理更新

打开首页先看到当前 Root、管理器和内核状态，再看到更新与系统摘要。安装、升级、SuperKey 认证和重启仍通过原有处理器执行。需要完整 Kasumi 信息时切换“系统”；查看注入运行情况时从原有 YukiZygisk 摘要进入“注入监控”。

### 管理应用授权

在“授权 → 应用”搜索或排序应用，点击应用进入原有配置页面。应用名称优先，包名、版本与状态作为辅助信息；较长文字和操作区域按可用宽度布局。

通用授权策略集中在“策略与模板”，包括原有配置模板、SuperKey 和默认卸载模块策略。单个应用的授权与配置仍在应用详情中进行。授权日志已开启时，“授权记录”显示原日志查看器；未开启时显示说明和“管理内核功能”入口，不会自动打开日志功能。返回记录页时会重新读取可用状态。

### 管理扩展及其运行环境

模块和插件共用“扩展”入口，各自保留搜索、状态、管理操作与原有业务处理器。仓库是独立工作区，从模块或插件进入时直接选择对应仓库标签；插件仓库源管理仍保留原入口。

挂载与注入设置从扩展工具栏进入。Kasumi 挂载参数与 YukiZygisk 的监控、配置分别呈现，减少在长页面中寻找控件。每个模块的挂载配置、WebUI 和快捷方式仍位于该模块的操作区域。

### 调整管理器设置

设置首页是六个清晰类别，而不是持续增长的选项列表。外观、内容与显示、应用与更新、维护与关于在同一设置导航中展开，工具栏与系统返回均回到类别索引。每个类别保留可保存的滚动与页面状态；再次进入时读取已有偏好。

外观仍支持既有品牌色、动态配色、浅色 / 深色 / 跟随系统、自定义背景、透明度、背景压暗、语言和 DPI。内容显隐只影响原有信息展示，不改变功能数据。更新开关、CI 更新条件、自动更新 ksud 和 WebUI 引擎偏好保持原逻辑。

### 查看隔离、内核功能与诊断

“内核与隔离”按隔离设置、生效规则、内核功能、高级安全分组。内核功能仍依据原有支持状态启用或禁用；需要重启、生效失败和回滚的反馈来自原处理逻辑。

诊断从设置进入，首页也提供快捷入口。“选项与导出”保留原诊断报告底部面板：保存使用 Android 系统文档选择器，分享使用系统分享面板。“运行日志”承载 Kasumi / 内核日志。WebUI 调试保留 `BuildConfig.DEBUG` 条件，Eruda 仍依赖已启用调试及对应 WebUI 引擎。

## 视觉与交互审查

遵循已加载的 `emil-design-eng` 技能，UI 审查使用 Before / After / Why 表格。技能中的实现思路按 Compose 与 Android 原生组件适配，不直接使用 Web CSS 或 JavaScript 示例。

| Before | After | Why |
| --- | --- | --- |
| 多个独立顶层入口，相关设置分散 | 四个底部目的地，按状态、授权、扩展与设置组织 | 日常任务入口稳定，减少往返 |
| Kasumi 与 YukiZygisk 的状态、配置、日志混在长页中 | 分别放入首页系统、挂载与注入、内核与隔离、诊断 | 同一目的的内容可以连续处理 |
| 设置逐项堆积，外观与安全设置混排 | 类别索引与聚焦子页 | 更易扫描，降低错误操作机会 |
| 大面积状态色块、独立数字卡与多层容器 | 中性表面、行内状态与单层分组 | 提高信息密度，突出关键操作 |
| 标题、包名、版本和状态争抢同一行 | 正文与辅助信息分级，长内容与按钮组按需换行 | 适应窄屏和放大的系统字体 |
| 图标操作缺少说明，状态依赖颜色 | 清晰文字按钮、语义标签与中性辅助信息 | 操作更直接，读屏不依赖视觉推断 |
| 高频导航使用明显位移、弹跳与持续装饰动画 | 即时标签切换、原生点击反馈与克制状态过渡 | 工具操作迅速，减少重复等待 |
| 悬浮菜单逐项弹出且高度固定 | 原生锚定菜单与可测量的文字布局 | 长标签、横屏和大字更稳妥 |
| 内容可能延伸到系统栏或输入法下 | 宿主统一处理安全区、消费 padding 并避让 IME | 避免底部操作与输入被遮挡 |
| 宽屏内容过宽，设置控件在读取前短暂显示默认值 | 居中限宽，初始化完成后显示可编辑设置 | 阅读更集中，避免误导性的初始状态 |
| 页面切换可能取消已触发的部分界面保存任务 | 对必须完成的持久化使用明确生命周期保护，并向宿主上报忙碌状态 | 保存结果与界面反馈一致 |

浅色模式以白色、浅灰色与深色文字为主；深色模式使用对应中性表面。既有品牌色和动态配色用于选中、主操作与重要状态。圆角、分隔线和阴影遵循共享主题，避免每行独立卡片和重复嵌套。旧外观选择器已移除，保留主题与用户个性化设置。

## 原生适配与状态管理

- 系统栏与键盘：`MainActivity` 统一提供 IME 避让和宽度约束，页面消费宿主 padding；嵌入内容不再创建重复顶栏或重复计算同一安全区。
- 屏幕宽度：主要内容居中限宽；标签页可横向滚动，按钮与辅助信息按可用空间换行。横屏和窄屏不依赖固定文本高度。
- 字体与无障碍：保留原生文字缩放、按钮 / 标签 / 开关语义；设置开关整行只暴露一个可切换目标，装饰图标不重复朗读，导航标签持续可见。
- 动效：高频工作区切换即时执行，状态反馈使用现有 Compose / Material 行为并遵循系统动画设置。加载和操作进度继续使用原生进度组件。
- 初始化：`MoreSettingsContent` 在既有配置和 SELinux 状态读取完成后才显示控件。切换类别不会把尚未读取的临时默认值当成用户选择写回。
- 保存：配置仍走原处理器。必须完成的内核功能持久化、运行时后续操作与必要回读不随页面离开直接中断；外观滑块最终保存与已开始的报告文件复制也受到保护。具体工作区忙碌状态由宿主用于限制中途切页。
- 状态恢复：工作区标签和可保存的子页面状态使用 Compose 原生保存机制。后台数据重新进入时仍从原数据源读取；监控只在相应页面活动时执行原有轮询。

设备验收需要覆盖：

1. 浅色、深色、动态配色与自定义背景；长应用名、包名、版本和路径。
2. 320dp 窄屏、横屏、平板宽度、2 倍字体以及系统更大的字体设置。
3. 手势导航、三键导航、状态栏、屏幕开孔与键盘弹出后的底部操作。
4. TalkBack 焦点顺序、设置开关、标签选择、图标说明、键盘返回与系统关闭动画。
5. 授权、扩展、设置类别的来回切换；返回前一页与屏幕旋转后的状态恢复。
6. 保存时尝试切页 / 返回、失败回读、需要重启的反馈；保证原业务结果和界面一致。
7. 未授权、未安装、内核功能不支持、授权日志关闭和非调试构建等条件页面。
8. 从文件选择器和系统分享面板返回后的状态；报告导出、模块 / 插件安装与维护确认流程。

Root 授权、内核配置生效和安装 / 还原行为必须在适合测试的 Android 环境中验证。静态审查和普通 JVM 单元测试不能替代这些运行验证。
